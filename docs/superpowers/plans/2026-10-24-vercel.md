# Vercel and browser profile implementation plan

Goal: host Bee’s Reader on Vercel with no account prompts or application database, isolated browser profiles, fullscreen reading and installable PWA behavior.

The latest user request supersedes the original SQLite/local-only requirements. User-confirmed profile behavior: profiles belong to each browser profile/origin, remain across reopen, do not automatically sync across devices, and can be backed up/exported. Different browsers/visitors do not share personal state. Shared devices using one browser profile share that browser’s profile.

Architecture: browser storage owns all personal data. Server routes remain read-only provider adapters with shared Vercel Runtime Cache for public metadata/cooldowns and bounded local pacing. Images stream through the existing SSRF-protected connection; no image mirroring. Manifest and a small service worker enable installation and a safe offline fallback, never caching chapter images/API data.
